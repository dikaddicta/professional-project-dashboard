# UI Copy and Business Language Review

This document defines the language standard used across the dashboard interface.

## Writing Principles

The interface should use wording that is:

- Clear
- Professional
- Concise
- Suitable for business users
- Consistent across Project Manager, Admin, and Client views

## Preferred Terms

| Area | Preferred Wording |
|---|---|
| Project access | Akses Project |
| Client account | Akun Client |
| Active access | Akses Aktif |
| Disabled access | Akses Dinonaktifkan |
| Project management | Kelola Project |
| Project editor | Edit Project |
| Schedule | Schedule |
| Report export | Export Report |
| Backup export | Backup Data |
| Client-visible information | Informasi yang tersedia untuk client |
| Internal agenda | Agenda Internal |

## Button Style

Buttons should use action-oriented labels:

- Simpan Agenda
- Buka Schedule
- Unduh Report
- Export Data
- Kelola Project
- Edit Project
- Aktifkan Akses
- Nonaktifkan Akses

## Empty State Style

Use helpful messages that explain the condition and next step.

Examples:

- Belum ada agenda project terdekat.
- Belum ada update project yang tersedia.
- Belum ada dokumen yang tercatat.
- Pastikan akun ini sudah diberikan akses ke project yang sesuai.

## Message Style

Use user-friendly operational messages.

Examples:

- Perubahan berhasil disimpan.
- Agenda berhasil diperbarui.
- Akses client berhasil dinonaktifkan.
- Data belum tersedia untuk project ini.

## Review Checklist

- UI does not use technical implementation terms.
- Client view uses stakeholder-friendly wording.
- Project Manager view remains operational and clear.
- Admin view does not mention restricted internal features.
- Empty states are helpful and not overly technical.
